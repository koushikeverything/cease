## 5. Verdict

### `hybrid`

**Leverage (build nothing):**

- All data access — Shopify, Gmail, Stripe, Notion, Calendar, Slack,
  Firecrawl, browser. `connectors.md` is explicit that building a second
  bridge to a service with a first-party connector "is a finding, not a
  feature". **No MCP server is to be written for this artifact.**
- All scheduling — spec §7's six scheduled tasks map onto the native
  `scheduled-tasks` surface (probed `works`). No scheduler is to be built.

**Build (the uncovered slice):**

The judgment layer, which no probed capability provides — fingerprint
synthesis and allowlist derivation, retrieve-then-classify detection, six-way
type classification, four-factor severity scoring, chain-of-custody evidence
assembly, per-platform instrument drafting, the mechanical pre-send signature
gate, the audit log, persistence/relaunch tracking, and the packaging that
makes it installable.

**Target class: `claude-plugin`.** Why not smaller:

- *agent-skill* — cannot ship a hook. R26 ("never auto-file") would then rest
  on instruction prose, which this repo's own `AGENTS.md` forbids
  ("invariants are enforced by capability, not prompt prose") and which
  carries real 17 U.S.C. §512(f) exposure. A skill also cannot ship the five
  investigator subagents or the six slash commands as one installable unit.
- *connector-solution* — its artifact shape is "one of the other three
  targets, or nothing". Here the hook + multi-skill + subagent + template
  surface resolves to a plugin.
- *mcp-server* — rejected above: every data source is already connector-covered.

**Evidence rows:** §2 rows for `SearchPlugins`/`ListSkills` (absent) establish
nothing exists to leverage wholesale; the §3 "Connector set alone" and
"scheduled-tasks" rows establish which parts are already covered; the Gmail
and Firecrawl-archival rows establish that two capabilities the spec assumed
(semantic mail search, crawl/archive) must be built or rerouted.

**What would flip this verdict:**

1. A brand-protection plugin appearing in the marketplace that covers
   R4 + R11–R13 + R26 → re-run discovery, likely `leverage` or a thin fork.
2. A decision to operate CEASE as a hosted multi-tenant service with its own
   auth and server-side state → target becomes a durable Eve agent under the
   sibling `koushik` lifecycle, not a plugin.
3. Stripe's connector proving unable to return dispute/chargeback objects
   (now deferred behind a fixture) → R6 degrades to manual import; the verdict
   holds, the requirement narrows.
4. Connectors becoming available → the fixture adapters are replaced with live
   sources and precision becomes measurable for the first time. The verdict
   does not change; what changes is that the product's central claim can
   finally be tested.
